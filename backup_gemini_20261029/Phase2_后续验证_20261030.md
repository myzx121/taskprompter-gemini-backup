# Phase 2 后续验证（2026-10-30）

本轮所有修改与输出均位于 `backup_gemini_20261029`，正式实验目录未改动。

## P0：闭式统计校准

已修复备份训练器的统计量初始化，使 `depth_coefficients` 与 `proper_rotation` 能在无梯度上下文中写入可训练参数，并在完整 161 张 dev 图像上完成 120 步验证。

| 配置 | mIoU | RMSE | normals° | edge loss |
|---|---:|---:|---:|---:|
| charge_none 基线 | 49.7998 | 0.610818 | 28.0215 | 0.051822 |
| charge_calibration（闭式初始化） | 49.8296 | 0.616508 | 28.0164 | 0.051822 |

结论：mIoU 仅增加 0.0298 个百分点，同时 RMSE 变差 0.00569；按“只保留大幅提升”的标准，P0 不进入正式实验。

## P1：身份保持双路径门控的结构验证

备份中的 `phase2_zero_init.py` 已改为残差式门控：初始输出严格等于 charge 路径，移除会破坏 step-0 恒等性的 LayerNorm，并保留 event-charge 差分的可训练门控。

验证结果：

- step-0 FiLM/LoRA/calibration/gate 最大误差均为 0；
- trainable parameters = 1,668；
- gate 梯度和 = 0.03916，LoRA-B 梯度和 = 4.89661；
- 全部零初始化不变量通过。

这证明 P1 的梯度与恒等性设计可行，但目前还没有接入 NYUD 完整训练器，因此不能把它宣称为性能提升。下一步应把该门控接入双专家推理路径后，再用同一完整 dev 集比较。

## 保留决策

本轮没有发现达到“大幅提升”标准的性能方案。保留 P1 的结构验证代码，舍弃 P0 的性能方案；正式实验保持原样。

在备份训练器中接入同种子 event/charge 冻结专家，以 `0.5 * event + 0.5 * charge` 作为可控对照，并在完整 dev 集运行 120 步：

| 配置 | mIoU | RMSE | normals° | edge loss |
|---|---:|---:|---:|---:|
| charge_none 基线 | 49.7998 | 0.610818 | 28.0215 | 0.051822 |
| dual_static_calibration | 49.7869 | 0.616519 | 28.0200 | 0.051822 |

静态均值混合没有带来提升，因此不保留为正式方案。它同时说明报告中提出的 P1 价值来自空间/任务条件化路由，而不是简单平均；下一步若继续，应直接测试身份保持的 Prompt+高频动态门控。
